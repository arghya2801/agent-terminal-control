# Bug and performance review (2026-11-20)

Review of `main` at 398f5c4 for bugs, CPU and memory. The first pass below was done by Opus with Sonnet helpers; items marked (sonnet) came from those helpers. Five Opus reviewers then re-checked each area; their results are under "Opus review". Ticked items are fixed on `fix/review-bugs-perf`.

## Still open

Try: CPU while a Claude terminal tab works, Ctrl+W right after opening a terminal tab (no leftover `powershell.exe`), closing a chat whose CLI died (no 5 s wait), searching transcripts for a Windows path, arrowing through the command palette while an agent works.

## Bugs

- [x] `agents.go:283-295` vs `249-259`: `write` holds `s.mu` across `stdin.Write`, `read` takes `s.mu` per line. Full pipes both ways deadlock every chat. Fix: separate write mutex.
- [x] `manager.ts:544-590`: a tab closed while `openTab` awaits `nextLayout`/`ptySpawn` orphans the shell. Fix: check `tabs.get(key) === tab` after each await, kill the returned id.
- [x] `manager.ts:561`: PTY `Channel` is never disposed on tab close. Late output writes to a disposed terminal.
- [x] `codex.ts:185-189`: `send` after the app-server died never settles. Fix: reject when `this.dead`.
- [x] (sonnet) `claude.ts:473-480`: closing a tab whose CLI already exited waits the full 5 s in `AgentClose`.
- [x] (sonnet) `agents.go:268`: sidecar crash never `KillTree`s, so Codex app-servers outlive it.
- [x] (sonnet) `claude.ts:33`, `agent.ts:205`: catalog has no timeout; a hung promise is cached per provider, ignoring account.
- [x] `costs.go` scan: Claude's partial last line is parsed and not advanced past, so it is parsed again later. Duplicate records in memory.
- [x] `app.go` `FrontendReady`: kills PTYs one at a time with a 2 s wait each. Kill all, then wait.

### Terminal and PTY

First-pass claim about the undisposed channel is mostly refuted: it disposes itself on `'x'`, which Kill always produces. Finding 2 is the real issue.

- [x] High. `manager.ts:544,588`: no `tabs.get(key) === tab` check after `nextLayout()`/`ptySpawn()`; closing within ~100-300 ms of opening (or during tab restore) orphans the shell.
- [x] Med. `manager.ts:562-581,893-900`: `ptyKill` returns before Go's last output and `'x'` (up to 200 ms drain); late events write to the disposed terminal and `ptyAck` an id Go already deleted (unhandled rejection). Fix: store and dispose the channel in `closeTab`.
- [x] Med. `manager.ts:527-538`: every OSC title change runs `notify()` -> `sync()` -> `resolveSessions` (O(tabs x sessions)), labels effect, `saveTabs` JSON. Fix: return early when title, activity and name are unchanged.
- [x] Med. `app.go:358-364`: `FrontendReady` kills and waits serially; restore after reload waits N x 200 ms to N x 2 s. Use `killAll`'s shape.
- [x] Low-med. `pty_windows.go:401-414` vs `365-374`: Kill releases `mu` before `TerminateProcess`, while the exit path's `cleanup` closes the handle. A reused handle value could terminate the wrong process. Fix: terminate and close under `mu`.
- [x] Low. `app.go:457-470`: a `PtySpawn` in flight across a reload inserts after `FrontendReady` cleared the map; nothing owns it until quit. Fix: compare `pageID` before inserting.
- [x] Low (CPU). `pty_windows.go:217-233,260`: 3-4 copies per read plus per-rune decode. Fresh buffer per read; `utf8.Valid` fast path.
- [x] Low (CPU). `manager.ts:570`: hoist the `TextEncoder`.
- [x] Low. `pty_windows.go:298`: CPR detection misses `ESC[6n` split across IPC pieces.
- [x] Low. `manager.ts:887-917`: double close fires close listeners twice.

- [x] High. `agents.go:288-293` with `:249`: `write` holds `s.mu` across `stdin.Write`; `read` needs it per line. Node's stdout is blocking on Windows, so a multi-MB image send while another tab streams freezes every tab and hangs `stop()` at quit. Fix: separate write mutex.

### Go index, watcher, costs, search

Measured on this machine: 258 Claude transcripts (321 MB), 31 Codex (113 MB), 29,280 Claude usage lines. "Est." costs are not benchmarked.

The Go-side view that `UsageContext` runs only on index updates is wrong on the frontend side: the effect also tracks `tabs` (see App shell, High). `AppendLog` is not hot (one caller) and the Codex `json.Marshal` dedup key is negligible.

- [x] High. `costs.go:294,396`: every Claude usage line kept as nested `map[string]any`, then JSON-cloned per `Rows` call to set `sessionId`. Est. 40-60 MB held for the app's life, 100-300 ms CPU per tab switch. Fix: typed record struct, no clone.
- [x] Med. `sessions.go:249-257`: match offset from `strings.ToLower(text)` used on the original; lengths differ for some letters (Kelvin sign, dotted I), so the snippet shifts and `snippet()` can index past the end and panic. Fix: `(?i)` + `regexp.QuoteMeta` on the original.
- [x] Med. `sessions.go:242`: pre-filter compares against raw JSON, so queries with `\` or `"` (Windows paths) never match. Fix: also test the JSON-escaped query.
- [x] Med. `sessions.go:234,242`: 1 MB buffer per file and a lowercase copy per line; est. ~290 MB + ~430 MB of allocation per full search here. Reuse one buffer.
- [x] Med. `index.go:383-399,419`: a growing Codex transcript sets `dirty`, so every scan rewrites the whole cache with fsync while Codex runs. Fix: not dirty on a resumed reader.
- [x] Med. `index.go:456`, `costs.go:51`: `EvalSymlinks` per session and per cost row; est. 5-10k syscalls, 30-100 ms per call. Memoize per call.
- [ ] Med. `index.go:359`, `costs.go:277`: Index and Costs both walk and `os.Stat` every file; `DirEntry.Info()` is free on Windows. Skipped: on NTFS `DirEntry.Info()` lags one write for a file its writer holds open, so a live Codex transcript would look unchanged.
- [x] Med. `app.go:204`: `arm` watches every directory under the Claude root (137 here vs 22 needed); subagent writes fire events, and each new dir re-walks. Watch root at depth 1 plus project dirs.
- [x] Low-med. `costs.go:428,593`: `priceFor` per record instead of per model; price files re-read and re-parsed per call.
- [x] Low. `costs.go:368-372`: `remember` marshals the whole ledger each call and holds it twice (`ledger` + `saved`).
- [x] Low. `costs.go:327-336`: a complete final line without newline is consumed again next scan. Fix: advance `offset` by the tail.
- [x] Low (uncertain). `costs.go:303`: on first read any id+timestamp line can overwrite `f.id`/`cwd`/`parent`; `index.go:219` guards with `r.Meta == nil`.
- [x] Low. `index.go:313,405`: JSON clone per session and of the whole snapshot; use `maps.Clone`.
- [x] Low. `index.go:298-301`: Codex `Meta` serialized twice in `index-go.json`.
- [x] Low. `costs.go:322`: Codex keeps whole token_count payloads incl. `rate_limits`.
- [x] Low. `app.go:433`: `AppendLog` uses non-atomic `os.WriteFile`.
